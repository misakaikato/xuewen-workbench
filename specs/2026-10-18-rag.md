## 0. 决策修订（2026-10-18 主人定）

1. **模型上 bge-m3**（BAAI，XLM-RoBERTa 底座，dense 1024 维，多语含中文繁简）。

3. **v2 生成改 OpenAI 兼容端点**（baseURL/model/apiKey 可配，默认 `http://localhost:11434/v1`，兼容 Ollama/LM Studio），替换原「Ollama 硬绑定」决策。
4. **新增 RAG 管理界面**（独立页面）：模型下载/导入/状态、索引构建/暂停/重建/进度、库统计、检索测试台、生成端点配置。

## 2. 架构与数据流

```
扫描快照/chokidar 增量 ─→ 切块器(结构化) ─→ rag.db(better-sqlite3)
                                             ├─ chunks(text原文, text_s归一, heading_path, prefix_hash)
                                             ├─ chunks_fts(FTS5, BM25 on text_s)
                                             └─ vecs(chunk_id, BLOB fp32)
查询: t2s(q) ─┬─ FTS5 topN ──┐
              └─ embed(q)·cos topN ─┴─ RRF(k=60) ─→ 分数量化1e-4稳定排序 ─→ 段落卡
```

- **嵌入运行时抽象** `EmbedRuntime`（统一接口 `ready()/embed(texts[])/dispose()`，输出 L2 归一化向量）：
  - `onnx`：@huggingface/transformers + onnxruntime-node，Xenova/bge-m3 fp16；win 尝试 CUDA EP（实测点），mac/兜底 CPU。
  - `mlx`：sidecar（`server/rag/mlx-embed.py`，JSONL over stdio；uv 置备 `dataDir/py/rag-venv`：mlx + mlx-embeddings + transformers）。mac 默认，探测失败自动回退 onnx 并在管理页标注。
  - `mock`：确定性哈希向量（`WORKBENCH_RAG_EMBED=mock`），供 e2e 与无模型冒烟。
- **模型文件**：`dataDir/models/bge-m3/{mlx-fp16,onnx-fp16}/`，跨库共享、按机器存储；`model.json` 记录文件清单 + sha256。下载源 `huggingface.co` → `hf-mirror.com`。
- **切块**（结构化，不按字数硬切）：md 按 ATX 标题层级成节，超长节（>600 CJK 字）按段落边界二次分组；块嵌入文本 = `标题路径\n\n正文`；docx 按段落分组（Word 标题路径后续升级）；json 数组按条目/对象按顶层键，字段名保留。锚点 = `{path, heading_path, ordinal, prefix_hash}`。
- **增量与续建**：`files(path, content_hash, done)` 为进度位；chokidar 重扫后仅重做 content_hash 变化文件；中断后从首个未完成文件继续。
- **按库隔离**：`sources/<dsId>/rag.db`；可重建缓存定位（删除后可全量重建）。

## 6. 风险与实测点

- win CUDA：onnxruntime-node 是否随包带 CUDA provider dll、Blackwell sm_120 支持版本——需在 win 机器实测，失败回退 CPU 不阻塞。
- MLX sidecar：uv 在打包环境的解释器获取；mlx-embeddings 对 bge-m3 的前向正确性（与 onnx 向量余弦抽检）。
- bge-m3 无需指令前缀；truncation 1024；GPU batch 32 / CPU 8。
- FTS5 中文分词：按字符 bigram 建索引（unicode61 tokenizer 不分中文词，bigram 召回足够且实现零依赖）。
