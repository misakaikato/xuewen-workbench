# 规格：中断恢复第 1 批——更新与安装

## 背景与目标
2026-11-03 对「上一次没做完的操作在下次启动时怎么处理」做了全面盘点，主进程（`electron/`）这一侧发现以下问题。本批全部修掉。

- **mac 安装包下载**
  - 直接写正式文件名：中断后下载目录里留下同名半截 DMG；如果那里本来就有用户自己下载的同名文件，会被截断甚至删掉。
  - 不走系统代理，没有重试，失败原因不记日志。
- **mac 准备安装中途退出**
  - 挂载点一直挂着。已实测：同一个镜像第二次挂载会报「资源忙」，在重启电脑之前，自动安装每次都失败，而且失败原因说不清楚。
  - `ditto` 不随应用退出，变成孤儿进程。
- **staging 目录**（`~/Library/Application Support/Xuewen Workbench/updates/staging`）：替换失败的各个分支、准备阶段崩溃之后都没人清理，约 1GB。
- **替换脚本 `mac-install.sh`**
  - 两次改名之间存在中断窗口：应用会从原位置消失。跨卷时这个窗口等于整份复制的时长。
  - 还原分支在目标路径已经有半截目录时，`mv` 会把备份塞进这个目录里面，却报告「已还原」。
  - 备份 `.Xuewen Workbench.app.old-*` 在多条路径上残留。
- **Windows**：关机或注销时不会触发 `will-quit`，下次启动误报「上次没有正常退出」。
- **`pending.json`**：非原子写入。

目标：中断不会让应用消失或损坏，不留下大体积残留，不误删用户文件，失败可以诊断，不误报。

## 非目标
- 不改后端（`server/`），那是第 2、3 批的内容。唯一的例外是 `server/diagnostics.js` 中由主进程调用的会话标记函数，必要时可以改。
- 不改界面组件；不改 Windows 的下载路径（electron-updater 自带下载缓存、sha512 校验和清理）。
- 不新增依赖。

## A. mac 安装包下载
完整执行 `specs/2026-11-03-mac-dmg-download.md` 的设计第 1–6 条，再加上下面第 7 条：

7. **跨次启动的中间文件**
   - `.part` 文件名带版本号。下次检查到的仍是同一版本时，从已有的 `.part` 续传；最终的 sha512 校验能保证装进去的不是坏包。
   - **下载记录**：应用下载过的 DMG（包括 `.part`）记录在 `userData/updates/downloads.json`，字段为路径、版本、时间。清理只针对这份记录里的文件，用户自己的文件一律不碰。
   - **不覆盖用户文件**：目标路径上已经有一个不在下载记录里的同名文件时，换一个不冲突的文件名，例如加 `-1`。
   - **清理过期 `.part`**：开始新版本的下载时，删除记录里其他版本的 `.part`。
   - **正常退出时**：`before-quit` 时如果还在下载，中止本次下载并保留 `.part`，供下次续传。
   - **清理已装过的 DMG**：启动时如果判定上次已经更新成功（`lastInstall.result === 'updated'`），删除记录里版本号 ≤ 当前版本的 DMG 和 `.part`，并同步更新记录。失败的那次保留 DMG，供用户手动安装。

## B. mac 自动安装
1. **启动时清理残留**，放在 `createUpdaterBridge` 早期执行，异步进行，不阻塞启动：
   - **卸载残留挂载**：执行 `hdiutil info -plist`，找出镜像路径在下载记录里、或者挂载点位于 `$TMPDIR` 下 `wb-dmg-*` 的挂载，逐个 `detach`，失败时再用 `-force` 重试一次。
   - **删除 staging 目录**：当前没有安装在进行时，删除 `updates/staging`。
   - **删除空的 `wb-dmg-*` 目录**：本应用在 `$TMPDIR` 下留下的空目录一并删掉。
2. **准备前再兜底一次**：`prepareMacUpdate` 挂载之前先检查这个镜像是否已经挂着，是的话先 `detach`，避免「资源忙」。
3. **`ditto` 随应用退出**：用户在准备阶段退出应用时（`before-quit` 时安装状态为 installing 且处于准备阶段），结束 `ditto` 子进程，并 `detach` 挂载点。
4. **替换脚本**
   - **缩短中断窗口**：先用 `ditto` 把新版本复制到目标所在目录，取一个临时的隐藏名 `.<名>.new-<ts>`，与目标同卷；然后连续执行两次 `mv`：旧版改成备份名，新版改成正式名。这样即使应用装在外置盘上，中断窗口也只剩两次同卷改名之间的几毫秒。复制失败就删掉临时目录、写失败结果、重开旧版，并且不动旧版。
   - **还原前先清理**：还原备份之前，如果目标路径已经存在，先 `rm -rf` 它，再把备份改回原名。
   - **所有失败分支都清理**：删除 staging 和临时的 `.new-*`，只有 `restore-failed` 例外，这个分支按设计保留备份。
   - **启动时补救**：`pending.json` 里记下备份路径。如果某次启动时发现，pending 里的备份还在、而目标版本已经正常运行，说明上次后台删除没做完，就删掉这份备份。
5. 继续沿用现有的测试开关 `WB_MAC_INSTALL_NO_OPEN`，规则不变：只在脚本内生效，派发时从环境变量中删除。

## C. 其余
1. **Windows 关机与注销**：在主窗口上监听 `session-end`，处理方式和正常退出一样：写会话结束标记（`markSessionEnd`），并把 `quitting` 置为 true，不再记录 `backend-exit`。
2. **原子写入**：`pending.json` 和下载记录都要原子写入：先写临时文件，再改名。

## 边界情况
| 情况 | 期望 |
|---|---|
| 下载到一半正常退出 | 保留 `.part`；下次同一版本续传 |
| 下载目录里有用户自己下载的同名 DMG | 不覆盖、不删除；换个文件名下载 |
| 上次准备阶段崩溃，挂载点还在 | 启动时自动卸载，再次自动安装成功 |
| 上次替换失败 | staging 和 `.new-*` 已清理；DMG 保留，供用户手动安装 |
| 还原时目标路径已有半截目录 | 先删除，再还原；备份不会被嵌进去 |
| Windows 开着应用关机 | 下次启动不误报 |
