# 规格：第 2 批——P1 缺陷修复（RAG 一致性、阅读页、编辑、Windows 文件语义）

日期：2026-11-02 ｜ 状态：施工中 ｜ 读者：施工者（无对话上下文也可施工）

## 背景与目标

只读审查（多数已实验复现）发现一组会让结果出错、丢输入或在 Windows 上不可用的缺陷。本批逐条修复，每条配自动化测试。成功标准：下列「验收标准」全部通过，既有测试与 e2e 不退化。下文行号基于第 1 批之前的代码，施工时以实际代码为准。

## 非目标

- 不做性能优化（全局重渲、引用扫描防抖、docx 图片外置、列表虚拟化等属第 3 批）；不做包体积、依赖清理、动效（第 4 批）。
- 不改检索 / 内链 / RAG 的算法与参数，只修状态一致性。

## 假设

1. 启动时对「已有 RAG 索引（files>0）」的库自动做一次增量对账续建，与「文件变化后自动增量」的既有设计一致；从未建过索引的库不自动建。
2. 阅读页检测到当前文档被外部改动时：非编辑态原地替换内容并保持滚动位置；编辑态不打断编辑，保存时走现有冲突流程。

## 设计（逐条）

### R1 RAG 索引一致性（`server/rag/manager.js`、`server/rag/store.js`）
- a. 构建中收到 `onScanComplete`（约 manager.js:245 现为直接 return）：记 `pendingRescan = true`；当前构建结束（成功、暂停、失败都算）后若有标记且未暂停，立即再跑一次增量。删除未使用的 `_autoQueued`。
- b. `store.replaceChunks`（store.js:117）写 files 行时 `done = 0`；`writeVecs` 成功后由 manager 调 `markFileDone`。无块的文件（空文本）可直接 done=1。
- c. 就绪判定（manager.js:55 附近 `status()`）：状态为 none 时，`files>0 && filesDone===files` **且** 对当前快照 `planIncremental` 结果为空（无待加、无待删）才视为 ready；否则为 `stale`（前端显示「待更新」，复用现有「建议重建」提示样式即可）。
- d. 启动续建：后端 boot 完成首次扫描后，对每个已打开且 `knowledge/<dsId>/rag.db` 存在且 files>0 的库，创建索引对象并触发一次增量构建（等文本索引就绪后）。
- e. 指纹：判定需要清库时，**清库的同一事务里**写入新的 `index_cfg` 指纹，之后暂停/失败/退出再续建不会再次清库。
### R2 阅读页不因任意写入整页重载（`src/pages/Read.tsx`）
- 文件加载 effect 去掉对 `config.status.scannedAt` 的依赖（约 Read.tsx:395）。
- 另起一个 effect 监听 scannedAt：从 store 的 tree（或新增的轻量接口 `GET /api/file/stat?path=` 返回 `{ mtimeMs, size }`，二选一，优先复用已有数据）判断当前文件 mtime 是否变化；未变化什么都不做；变化且非编辑态 → 拉取新内容并在现有 CodeMirror 视图内原地替换（`ReadOnlyDoc` 已支持原地 dispatch），保持滚动位置，不显示加载态；编辑态 → 不动。
- 保存自身触发的重扫不应引起任何可见变化。
### R3 切换文档不卸载整页（`Read.tsx`、`ReadAgentPanel.tsx`）
- 加载态只替换正文卡片区域，标签栏、工具栏、AI 面板、目录侧栏保持挂载；`DocTabs` 的横向滚动位置保持，并确保当前标签滚入可见区。
- `ReadAgentPanel` 的流式 fetch 用 AbortController，组件卸载时 abort。
### R4 划线笔记标记（`ReadOnlyDoc.tsx`、`Read.tsx`）
- noteMarks 改为通过 StateEffect 注入（与 `pushDocLinks` 同一方式），不再依赖 extensions 创建时的闭包；notesFor 晚到也能显示。
- `saveNote` 成功后重新拉取 notesFor，下划线与计数立即更新。
### R5 TXT 标记与 `?h=` 高亮（`Read.tsx:415-476`、`TxtReadBody`）
- 不再对 TxtReadBody 管理的 DOM 做 splitText；把笔记标记与高亮区间作为数据传给 TxtReadBody，由它在渲染分段时生成对应 span；链接数据晚到重渲后标记仍在。
### R6 助手编辑消息保存（`src/pages/AgentChat.tsx:562/626`）
- 编辑框改为受控（或用 ref 取 `.value`），「保存」按钮与 Enter 走同一条取值路径。
### R7 分栏预览内链（`src/pages/Edit.tsx:679`、`ReadOnlyDoc.tsx:176`）
- 预览内容更新防抖 300ms；内容替换按差异范围 dispatch（找公共前后缀，只替换中间变化段），未变化区域的内链保留；保存后既有的重拉逻辑不变。
### R8 检索框（`src/pages/Search.tsx:185-200`）
- 只在 URL 的 q 与 `input.trim()` 不同时才把 q 写回输入框；输入法组字期间（compositionstart→compositionend）不发请求，组字结束后再按防抖发。
### R9 Windows 盘符根目录（`server/index.js` `resolveWithin`）
- 前缀判断写成：`const prefix = baseNorm.endsWith(path.sep) ? baseNorm : baseNorm + path.sep`；realpath 分支同理。抽成一个 `isWithin(child, base)` 小函数，所有「是否在目录内」判断都用它（含 `read_doc`、skill 校验等第 1 批新增处，若其写法不同则统一）。
### R10 启动时不可达的库恢复后可救回（`server/index.js` `/api/rescan`、`addOrActivateLibrary`）
- 库没有快照（启动时不可达）时，`/api/rescan` 与重复添加同一目录都改为：目录可访问则调用 `lib.start()`（扫描 + 开监听），返回正常状态；仍不可访问返回 409 与原因。
### R11 .doc 转换隔离（`server/word.js:76-130`）
- 每次转换使用独立临时目录（`fs.mkdtempSync(path.join(cacheDir, 'convert-'))`），只读取本次在该目录新产生的 docx，用完删除目录；LibreOffice 正常退出但没有产物时视为失败并回退 word-extractor（与现有回退一致），不得读取任何其它位置的旧文件。并发安全。
### R12 「清除忽略」500（`server/index.js:1395`）
- `indexer` 改为 `lib.indexer`。
### R13 原子写在 Windows 上的占用重试（`server/index.js` `writeTextAtomic`、`server/store.js` `writeJsonAtomic`）
- `renameSync` 遇到 `EPERM`/`EACCES`/`EBUSY` 时按 50、100、200、400、800ms 退避重试；最终失败时删除临时文件再抛错。两处共用一个 `renameWithRetry` 函数（放 `store.js` 导出）。
### R14 换行符混用时内链偏移（`server/indexer.js:42`、`src/components/editor/lineSeparator.ts`）
- 服务端文本表示必须与前端 CodeMirror 的文档表示逐字符一致：抽出共享函数 `toEditorText(raw)`（放在前后端都已引用的共享模块，如 `server/linkMatch.js` 旁新建 `server/editorText.js`，前端经相对路径导入，与 `normalizeText` 的现有做法一致）：先去 BOM；`detectLineSeparator(raw) === '\r\n'` 时把 `\r\n` 换成 `\n`，否则原样（孤立 `\r` 与混入的 `\r\n` 中的 `\r` 保留）。`detectLineSeparator` 也移入该共享模块，前端原文件改为再导出，避免两份实现。indexer 用 `toEditorText`。
- 内链缓存签名需要变化（`MATCH_ENGINE_VERSION` 或 links 缓存版本 +1），保证老缓存失效。
### R15 仅改大小写的重命名（`server/index.js` rename 约 990-1013）
- 新旧名仅大小写不同时：若目标路径存在且 `realpathSync`/inode 与源不同（大小写敏感卷上真有两个文件）→ 409 `目标已存在`；相同（不敏感卷上的同一文件）→ 经中间临时名两步改名（`a.md → a.md.wb-case-<随机> → A.md`），旁注同理。
### R16 React 规则问题
- `src/components/FileTree.tsx:345` 条件调用 `useState`：把目录行拆成独立组件 `DirRow`，hooks 在其顶层。
- `src/components/Layout.tsx:68/92` 渲染期写 ref：改在 `useLayoutEffect` 中同步。
- 修完这两个文件的 eslint 错误数下降（不再有 rules-of-hooks / refs 报错）。
