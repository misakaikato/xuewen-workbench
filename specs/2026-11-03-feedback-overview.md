# 耗时操作反馈：总览与分批

## 背景
很多耗时操作点下去没有任何反应，要等到完成才出结果，用户会以为应用卡住了。最典型的是 Windows 更新：下载完点「重启并安装」，应用关掉之后要隔一段时间才出现新版本，中间什么都不显示。用户的要求：mac 和 Windows 都要有完整反馈，凡是耗时操作都要让人知道「正在做什么、做到哪了、做完或失败了」。

## 反馈分级（所有批次的统一口径）
| 预计耗时 | 必须给的反馈 |
|---|---|
| < 300ms | 不额外提示。指示器延迟 150ms 才出现，避免一闪而过 |
| 300ms – 3s | 按钮进入忙碌态（禁用 + 转圈）。完成或失败要有结果提示 |
| > 3s，或时长不可预期 | 在上一档基础上加阶段文字（正在做哪一步）；能算进度就给进度条和百分比；超过 10s 的加速度或剩余时间；能取消的给取消 |
| 后台进行、影响结果完整性 | 全局指示，并在受影响的结果旁标明「结果可能不完整」 |

另外两条硬规则：
- **失败必须可见**：不允许 `catch {}` 吞掉用户操作的失败。
- **后端不得同步阻塞**：同步阻塞会让所有轮询一起停住，进度在界面上冻结。

### 第 1 批：反馈基础件 + 应用更新（mac / Windows）
规格见 `specs/2026-11-03-feedback-batch1-update.md`。
- Windows 静默安装（`electron/updater.js` 的 `quitAndInstall(true, true)`），关闭到重开之间无任何界面。
- mac 未签名：现在打开 DMG 后退出，需要用户手动拖拽，也不会自动重启。
- 横幅（`src/components/UpdateBanner.tsx`）：
  - 点击后要等 0–5 秒界面才变化，按钮能重复点。
  - 进度每 5 秒才刷新一次，不显示速度和剩余时间，「重试」没有忙碌态，不能取消。

- 没有统一的 toast；按钮没有统一的忙碌态；`InlineLoading` 没有任何地方在用。
