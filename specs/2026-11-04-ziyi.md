# 规格：字义库（单字释义的检索、查询、编辑与阅读时查看）

## 背景与目标
老师有一套逐字讲解的字义数据（每字一个 JSON：`{ han, unicode, meaning, source }`，约三千字），希望在工作台里：
- 检索（按字、按释义/出处里的词）、查询单字、编辑与新建、删除；
- 阅读文档时随手查看：选中字或 Alt 点击单字，右侧出现字义，可当场修改。

字义数据**不随程序分发、不进仓库**：用户在「设置 → 字义库」导入一个 zip 字义包，数据存本机数据目录。没导入时，界面上除设置页的导入区外没有任何字义入口。

成功标准：导入真实字义包后，阅读页选中「宛」即可在侧栏看到释义并修改保存；字义页能按「屈曲」检索到「宛」；导出的 zip 再导入，数据逐字一致。

## 非目标
- 不实现 `docs/derived-data-protocol.md` 里按资料库、按语境的 `.derived/ziyi.jsonl`（那是另一种数据，仍未接入）。
- 不把字义接入内链、RAG、智能助手工具、全局检索页、命令面板。
- 不做拼音、多音字分条；一个 `han` 只有一条。
- 编辑页（CodeMirror 编辑模式）不提供查字义。

## 假设
- A1 字义库是全局的（与资料库无关），存 `<数据目录>/ziyi/`。
- A2 导入 = 以字义包为准整体替换；默认保留本地改过/新建的字（`editedAt` 非空），可取消勾选。每次替换或移除前自动把现有数据备份成 zip，保留最近 5 份。
- A3 繁简互通：查询与匹配都经现有 `normalizeText`（`server/linkMatch.js`，等长逐字映射）归一；查「棗」命中「枣」。
- A4 `unicode` 由 `han` 计算（单码点时为大写十六进制，否则 null），不存储、不信任包内的值。

## 现状（复用）
- 数据目录：`dataDir()`（`server/store.js`）。原子写：`writeJsonAtomicAsync`、`preserveCorrupt`（`server/atomicFile.js`）。
- 读 zip：`adm-zip`（已在依赖，`server/agent/routes.js` 用过）。写 zip：`writeZip`（`server/zip.js`）。
- 导出后定位：`revealInFolder`（`server/hostOpen.js`），模式同 `/api/diagnostics/export`。
- 路由挂载模式：`mountRag` → `app.use('/api/rag', ...)`（`server/rag/routes.js`）。
- 前端请求：`req`/`json`（`src/lib/api.ts`）；提示：`notify`（`src/lib/notify.ts`）；未保存守卫：`registerUnsaved`（`src/lib/unsaved.ts`）；确认框：`src/components/ui/alert-dialog.tsx`。
- 阅读页选区浮动条与右侧面板：`src/pages/Read.tsx`（`sel` 状态、`data-wb-selbar`、`aiOpen`/`ReadAgentPanel`、`sidePresence`）。
- 测试约定：后端 `scripts/test-*.mjs`（临时 `WORKBENCH_DATA_DIR` 起后端）；UI `scripts/e2e-*.mjs`（Electron）。

## 设计

### 存储
`<数据目录>/ziyi/entries.json`：
```json
{ "version": 1, "importedAt": "ISO|null", "sourceName": "文件名|null",
  "entries": { "<han>": { "meaning": "…", "source": "…", "editedAt": "ISO|null" } } }
```
内存中常驻一份，另存每条的归一化 `han/meaning/source` 用于检索。文件损坏：`preserveCorrupt` 改名保留，按未安装处理并记 WARN。所有写操作经同一个 Promise 队列串行。

备份：`<数据目录>/ziyi/backups/ziyi-<时间戳>.zip`（导出格式），超过 5 份删最旧。导出：`字义库-<时间戳>.zip`，与诊断包同口径放到 `WORKBENCH_DESKTOP_DIR`（Electron 设为桌面），不可写时回退 `<数据目录>/ziyi/exports/`；导出后在文件管理器中定位（请求体 `reveal:false` 时不定位，供测试用）。

### 字义包格式（导入与导出相同）
zip 内任意层级的 `*.json` 文件，每个是 `{ han, unicode?, meaning, source? }`。忽略：文件名以 `_` 或 `.` 开头、路径含 `__MACOSX/`、非 `.json` 文件。校验：`han` 为非空、无空白、≤ 8 个码点的字符串；`meaning` 为非空字符串；`source` 缺省为空串。不合格的 json 计入 `invalid`。同一 `han` 出现多次以后出现的为准，计入 `duplicates`。导出时文件名 `<han>.json`，内容 `{han, unicode, meaning, source}`，两空格缩进。

### 接口（全部在 `/api/ziyi`）
```
GET    /status                → { installed, count, editedCount, importedAt, sourceName }
POST   /import?keepEdited=1|0&name=<文件名>   body: application/zip 原始字节（上限 100MB）
       → { ok, count, added, updated, removed, keptEdited, invalid: string[≤20], invalidCount, duplicates, backup: string|null }
       错误：400 非 zip / 0 条有效（现有数据不动）
POST   /export  body { reveal?: boolean }  → { ok, file }   409 未安装
DELETE /                      → { ok, backup }  移除全部（先备份）
GET    /search?q=&offset=0&limit=50 (limit ≤ 200)
       → { total, items: [{ han, unicode, snippet, field: 'han'|'meaning'|'source', editedAt }] }
GET    /entry?han=X           → { entry: Entry, resolvedFrom: string|null }  404 无
GET    /lookup?text=…         → { items: [{ char, entry: Entry|null, resolvedFrom }] }
PUT    /entry  body { han, meaning, source, expectEditedAt?: string|null, create?: boolean }
       → { entry }   400 校验失败；404 更新的字不存在；409 { code:'conflict' } / { code:'exists' }
DELETE /entry?han=X           → { ok }  404 无
Entry = { han, unicode, meaning, source, editedAt }
```

### 核心流程
- **检索**：q 去首尾空白；空 q 返回全部，按码点排序。非空：按空白拆词，全部归一化；每个词须出现在该条 `han|meaning|source` 的归一化文本之一（AND）。排序：`han` 归一化等于 q 的归一化 → `han` 含任一词 → `meaning` 命中总次数降序 → 只在 `source` 命中；同级按码点。`snippet`：取第一处命中所在字段（han 命中时取 meaning 开头），前后各约 40 字的原文（归一化等长，偏移直接用于原文）；超出处加「…」。
- **查询/lookup**：先精确查 `han`；无则查 `normalizeText(han)`，命中时 `resolvedFrom` 为原字。`lookup` 对 text 按码点去重，跳过空白与标点（只保留 CJK 统一表意文字及扩展区、兼容区），最多 12 个。
- **编辑**：`create:true` 时 `han` 已存在 → 409 exists；否则新建，`editedAt=now`。更新：不存在 → 404；`expectEditedAt` 给出且不等于当前 `editedAt` → 409 conflict；成功则 `editedAt=now`。未安装时 `create:true` 会初始化一个空库（`sourceName:null`）。
- **导入**：解析 → 0 条有效则 400 → 现有已安装则先备份 → 按 keepEdited 合并（保留的本地条目覆盖包内同名字）→ 原子写 → 换入内存。`added/updated/removed` 相对导入前的库计算。

### 前端
- `src/lib/ziyi.ts`：模块级状态 + `useSyncExternalStore` 的 `useZiyiStatus()`（启动时读一次 `/status`，导入/移除/新建后刷新）；`api` 里的调用函数放在 `src/lib/api.ts` 的 `api` 对象里。
- `src/components/ZiyiEntryView.tsx`：一条字义的展示（大字、U+码点、释义 `whitespace-pre-wrap`、出处可折叠、「繁→简：由 X 查到」提示、本地修改标记）与原位编辑（释义、出处两个文本框，保存/取消，脏时 `registerUnsaved`，409 冲突提示重新载入）。字义页与阅读侧栏共用。
- 设置页「字义库」节（在「阅读与外观」之后）：状态行；「导入字义包（.zip）」文件选择；本地修改 > 0 时显示「保留我改过的 N 个字」勾选（默认勾）；导出、移除（确认框）；一句说明：字义包不随程序分发，数据保存在本机数据目录的 `ziyi/`。导入结果用 notify 显示新增/更新/删除/保留/无效数。
- 字义页 `/ziyi`（`src/pages/Ziyi.tsx`）：顶栏在已安装时出现「字义」链接。左栏检索框（200ms 防抖，结果高亮查询词，分页「加载更多」）+「新建」；右栏选中条目的 `ZiyiEntryView`；URL 同步 `?q=&han=`。未安装：空状态 + 去设置的链接。
- 阅读页：
  - 已安装时，选区（去空白后）长 1–12 且含汉字，浮动条出现「字义」按钮；长度 1 时只出现「字义」（「记笔记」「问 AI」仍要求 ≥ 2 字，未安装时行为与现在完全相同）。
  - 已安装时，按住 Alt（⌥）点击正文汉字：打开字义侧栏查该字，不触发链接。快捷键帮助表加一行。
  - 工具栏加字义按钮（已安装时）开关侧栏。字义侧栏与 AI 面板互斥（开一个关另一个），开着时目录/反链侧栏不显示。宽屏为右侧 aside（宽 360px），窄于 lg 时为固定右侧浮层。
  - 侧栏 `src/components/ZiyiPanel.tsx`：顶部输入框（输入字查询），下面按顺序列出每个字的 `ZiyiEntryView`；无条目的字显示「暂无字义」+「新建」；底部「在字义库中打开」跳 `/ziyi?han=`。

## 边界情况
- 未安装：`/search`、`/entry`、`/lookup` 返回 `installed:false` 语义的空结果（search total 0、lookup 每项 entry null、entry 404），不报 500。
- 上传非 zip / 损坏 zip → 400，现有数据不动。
- 导入与编辑并发：串行队列保证后写者基于前者结果；编辑基于旧 `editedAt` → 409。
- `entries.json` 损坏：保留 `.corrupt-*`，status installed:false。
- 超长释义：前端完整显示、侧栏可滚动。
- 代理项字符（扩展 B 区）：按码点处理，unicode 为 5 位十六进制。
