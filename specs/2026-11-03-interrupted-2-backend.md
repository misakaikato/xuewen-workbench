# 规格：中断恢复第 2 批——后端数据安全

## 背景与目标
2026-11-03 盘点了后端（`server/`）在中断后可能留下的问题。中断不只来自崩溃：正常退出应用时，主进程会在 `before-quit` 里直接杀掉后端（`electron/main.js`），所以用户关掉应用的那一刻正在进行的任务同样会被打断。本批修以下问题。

1. **H1 MLX 运行时解压到一半**：只要 `runtime/python/bin/python3` 存在就当作已解压。这个文件在包内第 13 项，标准库在几百项之后，所以中途打断时几乎总会留下没有标准库的运行时。之后每次都卡在 venv 创建失败，RAG 永久不可用（打包版 mac、未装 uv 时，即路径 B）。
2. **H2 复制文件夹到一半**：直接写入最终名「X - 副本」，出错的 catch 里也不删除，残缺副本会被扫描和索引，用户察觉不到。
3. **M1 `conversations.json` 非原子写**：每条消息都会写一次。写坏后解析失败返回空列表，之后再写入就把所有对话索引永久覆盖掉。
4. **M2 助手生成到一半被打断，以及重启后丢失上下文**：
   - 中断时已生成的回复只在内存里，整段丢失。
   - 每次 `_ensureSession` 都调用 `SessionManager.create`，重启、切库、换端点之后，模型不记得之前的对话，界面却仍显示完整历史。
   - 删除对话时不删 pi 的会话文件。
   - 显示用的 jsonl 最后一行被截断后，下一次追加会接在同一行上，连带丢掉下一条消息。
5. **M3 模型下载跨次重启**：已经完成并改名的大文件，下次会从头重下（约 1.1GB）。清单不是原子写入。
6. **M4 RAG「暂停」不持久化**：重启后自动续建，用户的暂停被无声撤销。
7. **M5 切块参数混杂**：首次构建中断后改了参数，或者构建过程中改了参数，新旧切块会混在同一个索引里，而且没有任何提示。
8. **L11 追加笔记**：`.<笔记名>.annotations.json` 非原子写。写坏后下一次追加会用只含新条目的数组覆盖，之前的划线记录全部丢失。
9. **L13 助手配置**：
   - `AGENTS.md`、`mcp.json`、编辑或删除消息时的整文件重写，都是非原子写。`mcp.json` 写坏后，新增服务器时会把其他配置全部清空。
   - skill 安装中断后留下的 `.tmp-*` 目录，会出现在技能列表里。
10. **L15 诊断确认文件**：非原子写。

**目标**：任何中断都不让数据静默丢失或被覆盖，不让功能永久坏掉；能续上的就续上。

## 非目标
- 不处理启动时统一清理、各类上限、缓存回收，这些是第 3 批的内容。
- 不改主进程，那是第 1 批的内容。
- 不改检索结果、切块算法和工具集。
- 不新增依赖。

## 设计
1. **H1 运行时**（`server/rag/embed.js`）：
   - 先解压到 `runtime.tmp-<ts>`，成功后检查 `python/bin/python3` 和 `python/lib/python3.12/os.py` 都存在，再把目录改名为 `runtime`，然后写完成标记 `runtime/.wb-complete`。
   - 判断「已解压」改为：标记存在。如果没有标记，但 `python3` 已经存在（旧版本留下的或者是半截的），就删掉整个 runtime 重新解压。
   - 解压失败或被取消时，删除临时目录。
2. **H2 复制文件夹**（`server/index.js` 的 duplicate）：
   - 先复制到同一目录下的隐藏临时名 `.<名>.wb-copy-<ts>`（扫描器会跳过以点开头的条目，这一点需要先确认），在临时目录里重写旁注 id，最后改名为最终名。
   - 任何一步失败，都删掉临时目录。
   - 单文件复制同样先写临时名，再改名。
3. **M1 对话索引**（`server/agent/manager.js`）：
   - `_saveMeta` 改用 `writeJsonAtomic`。
   - 读取解析失败时不再返回空列表让后续写入覆盖它，改为：
     - 把坏文件改名为 `conversations.json.corrupt-<ts>` 保留下来；
     - 扫描各库 `conversations/` 目录下的 `<convId>.jsonl`，重建索引：标题取第一条用户消息的前 30 个字，时间取文件修改时间，dsId 取所在目录；
     - 记一行 WARN。
4. **M2 助手**
   - **恢复完整会话**（用户已拍板）：
     - 对话元数据里新增 `piSessionFile` 字段，记录这个对话对应的 pi 会话文件路径。
     - `_ensureSession` 时，如果这个文件存在，就用 `SessionManager.open(piSessionFile, sessionDir)` 打开，接上之前的完整上下文，包括工具调用和工具结果；否则用 `create` 新建，并把新文件路径记回元数据。
     - 打开失败（文件损坏），或打开后第一次调用模型时报出与会话格式相关的错误：退回到新建会话，并把显示历史里的问答文字作为前置上下文交给模型；回退时记一行 WARN。
     - 「把显示历史作为前置上下文」的具体实现以 pi 的 API 为准（例如 `inMemory` 时传入 `entries`，或者第一条消息前置一段摘要），施工方选定后在报告中说明。
   - **中断时保留回复**：
     - 生成过程中，每累计约 2 秒或 2000 字，把当前已生成的回复写入一份「进行中」记录，可以是单独的 `<convId>.partial.json`，原子写入。
     - 正常完成时删掉它，并按原来的方式追加正式记录。
     - 启动或打开对话时如果发现这份记录，就把它作为一条助手消息追加进历史，带 `interrupted: true`；界面在这条消息上显示「（已中断）」。界面只做最小改动，复用现有的消息渲染组件。
   - **删除对话**：删除对话时一并删除它的 pi 会话文件和 `.partial.json`。
   - **截断行**：`_append` 追加前先检查文件最后一个字节是不是换行符，不是就先补一个换行符。
5. **M3 模型下载**（`server/rag/embed.js`、`download.js`）：
   - 逐个文件下载前，如果正式文件已经存在，并且大小等于远端大小（HEAD 或首次请求的 Content-Length），就跳过不重下。之后统一计算 sha256 写入清单。
   - 清单改为原子写入。
6. **M4 暂停持久化**（`server/rag/manager.js`）：
   - 暂停时，在 rag.db 的 meta 里写入 `paused=1`；开始构建（用户主动发起）时清除它。
   - 启动时的自动续建（`onScanComplete`）看到 `paused=1` 就不续建，状态显示为 paused。
7. **M5 切块参数**：
   - 构建开始时，如果 `index_cfg` 为空，先写入「构建中指纹」`building_cfg`。续建时比对它和当前参数，不一致就提示需要重建：沿用现有的 `configChanged` 字段，并且不自动混合构建。
   - 构建期间保存切块相关参数，返回 409「构建进行中，暂停或完成后再修改」。不影响切块的参数，比如检索参数，照常保存。界面上显示这条错误，沿用现有的错误提示。
8. **L11、L13、L15 原子写**：
   - annotations、`AGENTS.md`、`mcp.json`、诊断确认文件、编辑或删除消息时的整文件重写，全部改为「写临时文件再改名」，在异步上下文里用 `writeJsonAtomicAsync` 或等价写法。
   - annotations 和 `mcp.json` 解析失败时，不能静默当成空的然后覆盖写入：把坏文件改名为 `.corrupt-<ts>` 保留，再从空开始，并记 WARN。
   - skill 安装改为解压到 `skills/.<名>.tmp-<hex>`，用点开头；技能列表跳过以点开头的目录。

## 边界情况
| 情况 | 期望 |
|---|---|
| 解压运行时被取消 | 下次重新解压，可以成功 |
| 复制文件夹中途磁盘满 | 返回错误；库里没有「X - 副本」，也没有残留的临时目录 |
| `conversations.json` 是半截内容 | 对话列表能从 jsonl 重建；坏文件保留为 `.corrupt-*` |
| 生成到一半退出应用 | 重启后历史里有那条带「（已中断）」的半截回复 |
| 重启后继续追问 | 模型记得之前的对话和读过的文档 |
| pi 会话文件损坏 | 退回到用文字历史接上；记一行 WARN |
| 暂停后重启 | 仍然是暂停状态，不自动续建 |
| 构建中修改切块参数 | 409，有提示 |

  - **H2**：拉起后端，让复制在中途失败（例如源目录里放一个不可读的文件），断言返回错误、库里没有「X - 副本」、也没有 `.wb-copy-*`。再测一次正常复制成功。
