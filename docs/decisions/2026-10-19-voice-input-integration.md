# 2026-10-19 语音输入接入评估

状态：技术建议，待产品取舍；未实施功能。

本轮决策：为学问 Workbench 增加本地语音输入时，优先通过独立进程复用 Handy 的识别能力。先用现有 CLI 验证短句口述，再根据实测决定是否提取常驻 Rust 识别服务。不建议整体合并两个应用。

## 判据

- 中文及传统文化专名准确率、实际等待时间：35%。
- 插入目标正确、可撤销、不误发或误保存：25%。
- macOS / Windows 安装与运行可靠性：20%。
- 后续维护及上游升级成本：15%。
- 模型与录音的磁盘、内存开销：5%。

必须满足：识别在本机完成；原文保存规则保持成立；老师的目标机器不依赖开发目录或另一款应用的手动配置。权重是本轮工程判断，尚未经用户确认。

## 选项与建议

| 选项 | 收益 | 主要成本 | 判断 |
| --- | --- | --- | --- |
| 维持独立 Handy，用全局快捷键输入 | 马上能试用，零集成开发 | 双应用，依赖焦点和系统粘贴，无工作台上下文 | 作为体验基线 |
| 整体搬入 Handy | 保留原应用功能 | Electron/Node 与 Tauri/Rust 两套壳、设置、更新及打包；仍需重写桥接 | 不推荐 |
| 工作台录音，经 Handy CLI 转写 | 利用已有 JSON 接口，快速验证本地识别 | 单次进程冷启动、模型冷加载；不提供实时预览；沿用 Handy 配置和路径 | 推荐作为试点 |
| 提取常驻 Rust 服务，工作台统一交互 | 常驻模型、可接流式预览，故障隔离 | 要维护服务协议、模型管理和跨平台原生构建 | 推荐作为通过试点后的方向 |

## 已核对的事实

- Workbench：Electron 44 + React 19 + Express；桌面壳在 `electron/main.js`；目前没有录音或语音接口。现有 RAG 已使用 Python 子进程，进程间集成有先例。
- Handy：Tauri 2 + Rust，识别统一经 `transcribe-cpp`。录音、转写管理器依赖 AppHandle、设置和事件，不能直接复制成 React 功能。
- Handy 的 `--transcribe-file` 接受且校验 16 kHz、单声道、16 位整数 PCM WAV，返回 JSON 文本及加载/转写耗时。该路径跳过麦克风和窗口，不执行下载，每次调用均加载模型。
- 已运行本机打包版 `--help` 和 `--list-models --json`，均退出 0；后者约 3.14 秒，stdout 可直接解析。此数字只代表本机模型枚举耗时，不代表转写延迟。
- 本机模型列表中 Nemotron Streaming 3.5、Cohere Transcribe、MOSS-Transcribe-Diarize 显示已安装并包含中文；前者标记支持 streaming。模型元数据不能证明真实中文准确率。
- `engine_supervisor` 已有进程隔离、超时/取消、GPU 故障恢复与 CPU 回退，以及批量/流式协议。该层比应用管理器更适合提取，但仍须处理可执行文件定位、模型能力和文本处理策略。
- 代码为 MIT，复用时保留声明；Handy 名称、图标等品牌素材另有限制；模型授权需按所选模型单独核对。

## 推荐接入边界

工作台负责录音、焦点/插入位置、状态展示、草稿和保存；识别进程负责模型与推理。第一阶段提供“开始 → 停止 → 转写 → 回填”，聊天输入框优先，其次 Markdown 编辑器，再考虑搜索框。识别文本先进入可编辑内容，发送和保存继续由用户操作。

录音不能直接假定 MediaRecorder 输出就是所需 WAV；须明确采样、单声道混音、重采样及 PCM 编码。编辑器通过 CodeMirror transaction 插入并支持一次撤销。录音会话记录目标资料库、文件/会话及选区；返回时验证目标仍有效，失效则保留为待插入文本。

试点可复用本机 Handy 与已安装权重。正式版本统一管理语音配置和模型下载/导入；共享只读模型缓存，独立保存应用配置。Electron 补齐麦克风用途声明与权限处理。常驻服务只提供必要识别接口，保留 worker 故障隔离；模型按需加载并空闲卸载。

实时文本先放预览区，结束后一次插入；临时修订不持续写入文档。不在首版引入全局粘贴、语音命令、自动润色或整套 Handy 设置页。

## 关键未知与验证

尚未实测录音、真实转写、领域专名准确率、流式中文效果或 Windows 安装包。选择模型前，用真实说话人的短问句、含专名讲稿、中英混读、停顿/静音样本比较纠错负担，分别计冷/热启动与停止到文本可用的时间。若首版要求边说边出字，应直接做常驻服务，不把一次性 CLI 当最终接口。

## 预死亡与复盘

1. 演示能跑，老师机器不能跑：模型和原生资源依赖开发机。对冲：在干净 macOS / Windows 打包环境验收。
2. 识别一般，专名纠错抵消口述收益：对冲：先测领域样本，热词按模型能力接入；保留原始识别，自动纠词可关闭。
3. 转写回来时已换文档而插错位置：对冲：会话绑定目标，验证失败转为待插入，不自动改写别的缓冲区。

复盘点：首轮真实语音样本与干净安装验证完成后；如需要应用外输入、实时转写或离线分发，重新评估服务边界与打包范围。
