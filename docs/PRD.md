## 1. 产品定位
- 一句话：给一位教传统文化的老师（尊称）用的本地桌面工作台，集中阅读、检索、编辑老师的全部文字，并能用自然语言在这些文字里找答案。
- 用户：老师本人（主要使用者），主人（整理与维护）。
- 语料：老师自己写的文章、上课讲稿、知乎问答；格式 doc / md / json，基本是纯文本，约几百份，会持续新增。
- 二次加工数据：graphml 知识图谱、讲课字义（json）、自动总结、主题与概念及其反向索引。
- 不是什么：不是出海工具站，不是云服务，不是“AI 代写”。

## 2. 硬约束【已定】
- 必须本地运行；语料和加工数据保密，不出主人/老师的电脑，不进任何远程仓库。
- 桌面应用，支持 macOS 和 Windows（Electron 壳；先出 macOS，Windows 后续）。
- 代码用 git 管理，仅在本地。
- 原文是唯一的“真”：任何加工结果、链接、AI 内容都不改写原文。

## 3. 功能范围
### 3.1 文档库
- 【已定】指定语料文件夹，自动加载 doc / md / json；首次打开选择一次，之后记住。
- 【已实现，待主人手动验收】在指定目录下新建文档：选类型（文章 / 讲稿 / 知乎）、填标题，同时生成正文（默认 md）和 .meta.json，id 自动分配。
- 【已排期，下一项】在软件里改名、移动、删除时，.meta.json 同步处理；软件外移动造成配不上的，扫描时提示，不静默丢弃。
- 【建议】老式 .doc 需先转换；json 按条目读取，保留字段名。

### 3.2 阅读与编辑
- 【已定】编辑体验类似 Typora：保持 markdown 源格式的即时渲染编辑（开发选定 CodeMirror 6 实时预览）。
- 【已定】保存时不改写原文格式（列表符号、空行、标题写法保持原样），避免 git 出现无意义改动。
- 【建议】排版优先照顾长时间阅读中文（可能含繁体）：正文字体、字号、行距。

### 3.3 检索与知识库问答
- 【已定】精确检索 + 语义检索混合。
- 【建议】繁简体互通；按标题 / 段落切块，带书名、篇名、类型等信息。
- 【建议】第一版只做“检索 + 排好序的原文段落”，每条带出处，点击跳回原文并高亮；没找到就明说。本地大模型生成回答作为可开关的第二步。
- 【建议】用别名和相关概念扩展检索；结果先给命中的概念 / 字义卡片，再给原文段落。
- 【建议】准备 20–30 个老师真实会问的问题和应找到的段落，作为验收集。
- 【建议】本地向量模型（候选 bge-m3，开发实测）首次启动下载或指定目录，不打进安装包；首次建索引有进度条、可中断续建。
- 【暂缓】HyDE、自动出题。

### 3.4 自动跳转链接与反向链接
- 【已定】自动发现文档中能指向其他文档 / 概念的关键词，显示时加跳转链接，不改原文。
- 【已定】词表 = 文档标题（优先 .meta.json 的 title，回退文件名；排除 讲稿1、日期、未命名、单字等）、各级标题、概念条目的名称和别名（如 孔子 / 仲尼 / 夫子）；繁简互通；新建或改名后自动更新。
- 【建议】长词优先；同一词每节只链第一次；不链向自身；常见单字（天、道、心）可加入屏蔽词表，由老师维护。
- 【建议】每篇显示“提到本篇的文档”（反向链接）。

### 3.5 二次加工数据整合（详见 research/derived-data-design-2026-10-17.md）
- 【建议】所有加工结果通过「文档 id + 段落锚点」指回原文，可一键跳回高亮。
- 【建议】统一条目模型：概念 / 主题 / 人物 / 书名统一为“条目”（名称、别名、出现位置）；反向索引由“出现位置”直接得出。字义、图谱关系、每篇摘要各自一张表。内部存 JSONL，graphml 只做导入导出。
- 【建议】每条记录标明来源（生成工具与版本、时间、原文指纹）和状态（机器生成 / 老师确认 / 老师修改）；老师改过的锁定，重跑只给“建议更新”。
- 【建议】原文改动后相关条目自动标“待更新”；新语料只做增量加工。
- 【建议】入口：左侧导航 文档 / 概念 / 字义 / 图谱；阅读右栏显示本篇摘要、涉及概念、反向链接；单字可点开看字义（默认关）；图谱默认只显示当前文档或概念周边一两层。
- 【建议】管理：“加工任务”面板（覆盖率、待更新数、只跑增量）；概念合并、别名编辑、屏蔽词；旧数据一次性导入并出映射报告。
- 待办：菠萝在主人 Mac 上用只读脚本输出现有文件结构（只出字段名 / 类型 / 数量，不出正文），据此定字段。

### 3.6 元数据【已定】
- 每篇文档旁放同名 `.meta.json`，md 不写 YAML 头；id 生成后永不改。
- 【建议】命名带原扩展名：`论语讲稿.md.meta.json`。
- 【建议】字段：id、title、type（article / lecture / zhihu）、date、source_url（知乎原链接）、aliases、tags、content_hash；最终以现有文件结构对照后为准。

### 3.7 界面
- 【已定】美观、现代，像写文字用的工作台；先出视觉原型再改代码。
- 已出原型 A 宣纸书卷 / B 现代极简 / C 夜读暗色，每套含 阅读与编辑、知识库提问、首次建索引 三个界面（prototypes/）。待主人选定方向。

### 3.8 辅助写书【暂缓，主人再想】
- 调研结论：定位“基于老师原文编书”，不做“AI 写书”。候选 v1：书稿目录、右侧资料区、可溯源的引文块、按概念起章、段落批注、快照、Pandoc 导出 docx。详见 research/book-writing-tools-2026-10-17.md。
- 待确认：讲稿成书还是专题文集；出版社及格式要求；经典引文是否另行核对；谁整理、谁确认。

## 4. 建议开发顺序
1. 定 id 与段落锚点规则；.meta.json 生成与同步；新建文档
2. 编辑器（CodeMirror 6 实时预览，保存不改写）
3. 混合检索 + 带出处的原文段落；验收问题集
4. 旧加工数据导入 + 阅读右栏 + 概念页 + 自动链接 / 反向链接
5. 字义入口；加工任务面板（增量）
6. 图谱视图；Windows 包；本地大模型生成回答（可选）
